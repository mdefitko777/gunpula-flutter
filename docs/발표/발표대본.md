## 데모 준비 (발표 전 · 노트북)

1. 터미널 1: `cd mock_server && npm start` → `http://localhost:3000/kits` 가 열리는지 확인
2. 터미널 2: 저장소 루트에서 `flutter run -d chrome` → Chrome 창은 **좁게(폰 크기)** 시작
3. 데모 순서 연습 (약 1분):
   1. **홈** — 배너가 넘어가는 것을 보여 주고, "최근 추가" 첫 카드의 **리본**을 한 번 누른다 (✓ 로 바뀜)
   2. **카메라** — 가운데 카메라 → 찍기 → "AI가 비교하는 중…" → 후보 · 일치도 (미리 정한 결과)
   3. **컬렉션** — 아래 탭 컬렉션 → 구매함에 방금 담은 상품이 있다
   4. **도감** — 컬렉션의 도감 보기 → 작품 하나 → 칸의 리본을 누르면 칸이 켜지고 Lv 막대가 오른다
   5. **창 넓히기** — Chrome 창을 700px 넘게 늘리고 상품 하나를 누른다 → 왼쪽 앱 · 오른쪽 상세
   6. **오류** — 터미널 1에서 `Ctrl + C` → 앱 위 채널 바에서 다른 채널을 누른다 → 오류 + "다시 시도" → `npm start` → "다시 시도"
4. 막히면: 부록 B1(14–16장) 스크린샷으로 같은 순서를 설명한다. 오류 화면만 따로 보이려면 `flutter run -d chrome --dart-define=DEMO_STATE=error`

**한국어**

Gunpula v2는 피규어와 프라모델을 모으는 20대 수집가를 위한 앱입니다. 관심 있는 IP만 골라 새 소식을 보고, 갖고 싶은 건 하트, 산 건 리본으로 한 번에 기록합니다. 모을수록 도감이 켜집니다. 바탕이 된 hobbyDB는 별점 4.8이지만, 리뷰에는 "레이아웃이 고통스럽다"는 말이 있습니다.

**中文**

### 07 · 해결 방법 (1:00)

**한국어**

그래서 화면 구조부터 바꿨습니다. 대표 화면인 홈입니다. 1번, 맨 위 채널 바로 관심 있는 IP만 봅니다. 2번, 공식 예고 배너는 4초마다 넘어갑니다. 3번, 새 소식 줄에는 사진과 이름만 둡니다. 4번, 사진 위의 리본과 하트로 바로 담습니다. 상세는 쌓고, 시세는 시트로 덮고, 탭 사이는 옆으로 갑니다. 색은 두 개만, 파랑은 고른 것, 민트는 가진 것입니다. 상태관리 포인트는 좋아요와 구매함인데, 이번에는 표시만 하고 저장은 하지 않습니다.

**中文**

### 08 · 셀프 논증 (1:00)

**한국어**

셀프 논증입니다. 쟁점은 좋아요와 구매함을 어떤 모양으로 누르게 할까였습니다. 처음에는 자리마다 다른 모양이 좋다고 생각했습니다. 그래서 AI에게 UI 설계의 문제를 지적해 달라고 반론을 요청했고, 같은 구매함이 서너 가지 모양이라 일관성 원칙에 어긋난다는 답을 받았습니다. 리뷰에도 쇼케이스와 컬렉션의 차이를 모르겠다는 말이 있어서 받아들였습니다. 이제 하트는 좋아요, 리본은 구매함, 어디서나 같습니다. 왼쪽이 전, 오른쪽이 후입니다. 반대로 AI가 낸 알약 필터는 제가 폐기했습니다.

**中文**

### 09 · Flutter 구현 (0:45)

**한국어**

구현은 Flutter입니다. 화면 이동은 쌓기, 옆으로, 덮기 세 가지입니다. 데이터는 json-server에서 GET만 하고, 모든 화면에 로딩, 오류, 빈 상태가 있습니다. 창 너비에 따라 폰, 가로 폰, 폴드 반반 화면으로 바뀌고, 테스트 53개로 확인했습니다. 상태관리 패키지 없이 setState를 맨 위로 올려 화면끼리 같은 값을 보여 줍니다.

**中文**

实现用 Flutter。画面跳转有叠加、横向、覆盖三种。数据只从 json-server 做 GET，所有画面都有加载、错误、空状态。根据窗口宽度切换手机、横屏、折叠屏分屏，并用 53 个测试确认。没有用状态管理套件，把 setState 放到最上层，让各画面显示同一份数据。

#### 예상 질문과 답

**Q1. AI 반론 중 받아들이지 않은 것은 무엇인가요?**

AI가 처음 낸 "좋아요 · 구매함 알약 필터"는 폐기했습니다. 사용자는 상태가 아니라 작품별로 찾기 때문에, 오른쪽 필터 패널로 작품 · 종류 · 라인을 고르게 바꿨습니다. 부록 B3 prompt-log 10/25 줄에 있습니다.

> 问：AI 的反驳里有没被接受的吗？答：AI 最初提出的"喜欢/已购买胶囊筛选"被我否决了。用户是按作品找东西，不是按状态，所以改成右侧筛选面板，选作品、种类、系列。见附录 B3 prompt-log 10/25 那一行。

**Q2. 상태관리 패키지 없이 화면끼리 값을 어떻게 맞췄나요?**

맨 위 StatefulWidget의 setState를 InheritedWidget으로 내려 줍니다. 그래서 홈에서 리본을 누르면 컬렉션과 내 정보 숫자가 같이 바뀝니다. 저장은 하지 않아서 앱을 끄면 처음 값으로 돌아갑니다. 부록 B5-5에 있습니다.

> 问：没有状态管理套件，画面之间怎么同步？答：把最上层 StatefulWidget 的 setState 通过 InheritedWidget 往下传，所以首页点丝带，收藏页和个人页的数字一起变。不做保存，关掉 App 就回到初始值。见附录 B5-5。

**Q3. 카메라 인식이나 AI 후보는 진짜인가요?**

아닙니다. 미리 정해 둔 결과로 흐름만 보여 줍니다. 저장이나 전송은 없고, 이 사실은 디자인 가이드 4장 "가짜 기능은 가짜라고"에 밝혀 두었습니다.

> 问：相机识别和 AI 候选是真的吗？答：不是，是预先设定的结果，只演示流程，没有保存或传输。这一点写在设计指南第 4 章"假功能要说明是假的"。
