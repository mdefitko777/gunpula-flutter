## 데모 준비 (발표 전 · 노트북)

1. 터미널 1: `cd mock_server && npm start` → `http://localhost:3000/kits` 가 열리는지 확인
2. 터미널 2: 저장소 루트에서 `flutter run -d chrome` → Chrome 창은 **좁게(폰 크기)** 시작
3. 데모 순서 연습 (약 1분):
   1. **홈** — 배너가 넘어가는 것을 보여 주고, "최근 추가" 첫 카드의 **리본**을 한 번 누른다 (✓ 로 바뀜)
   2. **카메라** — 가운데 카메라 → 찍기 → "AI가 비교하는 중…" → 후보 · 일치도 (미리 정한 결과)
   3. **컬렉션** — 아래 탭 컬렉션 → 구매함에 방금 담은 상품이 있다
   4. **도감** — 컬렉션의 도감 보기 → 작품 하나 → 칸의 리본을 누르면 칸이 켜지고 Lv 막대가 오른다
   5. **창 넓히기** — Chrome 창을 700px 넘게 늘리고 상품 하나를 누른다 → 왼쪽 앱 · 오른쪽 상세
   6. **오류** — 터미널 1에서 `Ctrl + C` → 앱 위 채널 바에서 다른 채널을 누른다 → 오류 + "다시 시도" → `npm start` → "다시 시도"
4. 막히면: 부록 B1(18–20장) 스크린샷으로 같은 순서를 설명한다. 오류 화면만 따로 보이려면 `flutter run -d chrome --dart-define=DEMO_STATE=error`

#### 예상 질문과 답

**Q1. AI 제안 중 받아들이지 않은 것은?**

AI가 처음 만든 화면 자체를 버리고 제가 다시 설계했습니다. 또 상태로 거르는 목록, 알약 필터, 로고 시안도 폐기했습니다. 부록 B3 prompt-log에 있습니다.

> 问：没接受的 AI 提议？答：AI 最初做的整个画面我都推翻重新设计了；按状态筛选的列表、胶囊筛选、Logo 草案也都否决了。见附录 B3。

**Q2. 상태관리 패키지 없이 화면끼리 값을 어떻게 맞췄나요?**

맨 위 StatefulWidget의 setState를 InheritedWidget으로 내려 줍니다. 홈에서 리본을 누르면 컬렉션 숫자가 같이 바뀌고, 저장은 하지 않습니다. 부록 B5-5에 있습니다.

> 问：没有状态管理套件怎么同步？答：最上层 StatefulWidget 的 setState 通过 InheritedWidget 往下传，首页点丝带收藏页数字一起变，不做保存。见附录 B5-5。

**Q3. 카메라 인식이나 AI 후보는 진짜인가요?**

아닙니다. 미리 정해 둔 결과로 흐름만 보여 줍니다. 저장이나 전송은 없습니다.

> 问：相机识别和 AI 候选是真的吗？答：不是，是预设结果，只演示流程，没有保存或传输。
